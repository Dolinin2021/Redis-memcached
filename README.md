# Практическое задание с самопроверкой «Кеширование Redis/memcached»

## Задание 1. Кеширование
*Кеширование* решает проблемы высокой задержки отклика, перегрузки баз данных и сетевого трафика, повторного выполнения сложных вычислений, а также потери доступности данных при сбоях.
Сохраняя копии часто запрашиваемых данных в быстрой памяти, система позволяет мгновенно отдавать готовый результат вместо того, чтобы каждый раз заново обращаться к медленному источнику или пересчитывать информацию.

*Основные проблемы*, которые решает кеширование:

• **Медленная загрузка страниц и высокий отклик (Latency).** Когда пользователь открывает сайт, браузеру приходится скачивать картинки, стили и скрипты с удаленного сервера. Локальный кеш браузера и CDN сохраняют эти файлы ближе к пользователю, что сокращает время загрузки до миллисекунд. \
• **Перегрузка баз данных.** В высоконагруженных проектах тысячи пользователей могут одновременно запрашивать одни и те же данные, например, список популярных товаров или ленту новостей. Кеш (такой как Redis или Memcached) берет эти запросы на себя, снижая количество обращений к основной базе данных и предотвращая ее падение. \
• **Высокая стоимость и длительность сложных вычислений.** Формирование аналитических отчетов, рекомендаций или рендеринг сложных графиков требует больших ресурсов процессора. Если сохранить готовый результат в кеш, системе не придется тратить вычислительные мощности на повторный расчет при каждом новом запросе. \
• **Ограничения и лимиты внешних сервисов (API).** Многие сторонние сервисы (например, карты, курсы валют или прогноз погоды) ограничивают количество запросов в минуту или берут плату за каждое обращение. Кеширование ответов от таких API на определенное время позволяет уложиться в лимиты и сэкономить бюджет. \
• **Чрезмерное потребление сетевого трафика.** Постоянная передача одних и тех же тяжелых файлов (видео, изображений, обновлений ПО) забивает каналы связи. Промежуточные прокси-серверы и CDN разгружают основной канал, отдавая контент из локальных узлов. \
• **Временная недоступность основного сервера.** Если главный сервер или база данных временно вышли из строя, система может продолжать отдавать пользователям слегка устаревшие, но рабочие данные из кеша, сохраняя базовую работоспособность приложения.
